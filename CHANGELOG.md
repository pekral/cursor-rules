# Changelog

All notable changes to `cursor-rules` will be documented in this file.

## [Unreleased]

- 🔥 **Removed** `refactor(code-review)`: **the Commit Split & Atomic Deployability gate is gone — the CR report no longer renders a `## Commit Split Proposal` section.** The gate reviewed the shape of the commit history on every run and raised a **Critical** finding with a full repartition table, which turned every history judgement into a merge blocker and pushed the proposal, its green / live invariants, and its Suggested-Fix templates through every CR surface. Removed end to end: `@rules/code-review/general.mdc` loses the *Commit Split & Atomic Deployability — a first-class review dimension* section, the *canonical walk-through* section, the Core Analysis bullet, and the gate's slots in the *Highest-Priority Fast Track* and *Late-Iteration Report Scope* sections; `@skills/code-review/SKILL.md` loses the gate and its output rule; the four CR output templates lose the `## Commit Split Proposal` section, its Critical-bucket pointer, and the `commit split: N commit(s) proposed` summary slot; `@skills/code-review-github`, `@skills/code-review-jira`, and `@skills/code-review-bugsnag` lose the section rule and the ordering entry; `@skills/process-code-review/SKILL.md` loses the commit-split exemption and the `**History:**` line; and `@skills/pr-staged-merge-plan/SKILL.md` now defers commit-level reshaping to `@rules/git/general.mdc` *Git Rules* instead of the removed gate. The git-side commit invariants (*logical partition*, *Every commit is green*, *Every commit is live*, *One phase = one commit*) stay in `@rules/git/general.mdc` — they are authoring rules, only the CR report section and its Critical finding are removed.
- ✨ **Added** `feat(code-review)`: **CR's Suggested Fix for redundant comment narration is now rename / extract / name-the-constant, not plain deletion, and Exception 1 protects only the naming residue.** `@rules/code-review/general.mdc`'s Core Analysis index lens previously said only "require its deletion" for redundant *what*-narration, contradicting the canonical *Self-Documenting Code — Comment & Doc Hygiene Analysis* section it links to, which already required renaming or extracting first; the index now names the same remedy, with the pinned merge-gate severity tail left byte-identical, and its exception carve-out is qualified the same way — it no longer claims a rationale block is unconditionally exempt. Exception 1 ("knowledge the code cannot express, never delete") previously shielded a *why* comment unconditionally, so a multi-line rationale block sitting on a condition built from unnamed literals — e.g. `if ($firstFailedGuard === 'passport') { // The passport guard is a bearer-token guard... }` — was never flagged even though the condition itself could be named. Exception 1 now carries a naming-first precondition: it protects only the residue that survives after the code has been made to say everything it can (named constant, intention-revealing guard method, renamed variable); an unreduced rationale block is the *over-documented block* finding instead, gated so the two never double-count the same line, and the precondition explicitly never reaches a load-bearing comment another rule's exception depends on. The precondition is wired through every surface that decides whether a finding fires — the keep-bar, the over-documented-block trigger, and the closing gate — not only Exception 1 itself, so the reference `passport`-guard example above deterministically raises the finding instead of routing to zero findings. The require-deletion finding also now explicitly exempts tooling-mandated docblocks (generics a static analyzer needs), licence/copyright headers, and framework/generator-consumed annotations. On the authoring side, `@rules/php/core-standards.mdc` *Documentation* gained a matching "the *why* bar covers only the residue" clause, a standalone "tooling-mandated annotations are kept" bullet, and a link to the new `rules/php/examples/self-documenting-code.md` worked before/after, where every `Prefer` block keeps the residue its `Avoid` comment carried.
- ✨ **Added** `feat(code-review)`: **a static-analysis / linter suppression is never allowed in a diff — not even for an "unfixable" third-party false positive, and neither is a config-level equivalent with the same effect.** `@rules/php/core-standards.mdc` PHP Practices and its mirroring CR lens in `@rules/code-review/general.mdc` (*New static-analysis / linter suppression introduced*) already flagged a new PHPCS / PHPStan / Psalm / Phan / PHPMD / `@`-operator suppression as Moderate, but both carried a narrow escape hatch: a suppression was accepted when it was scoped to a single rule identifier and carried an inline comment explaining why the underlying issue was an "unavoidable third-party / framework false positive". That hatch let a tool finding get silenced instead of fixed, which is the exact outcome the rule exists to prevent. Both files drop the exemption outright — the only remaining non-finding is `assert($variable !== null)` for a required-but-unused variable, because that is a real assertion resolving the warning, not a suppression annotation — and both now name the config-level bypass that has the same silencing effect without ever needing an inline annotation a diff-scoped review could catch: a new `excludePaths` entry or a lowered `level:` in `phpstan.neon`, a removed rule or a new `<exclude name>` / `<exclude-pattern>` in `phpcs.xml` / a ruleset, a disabled rule in `pint.json`, a new `skip()` entry in `rector.php` (this project's own `rector.php` already carries one, pre-existing and untouched by the rule since it binds only to lines a diff adds or modifies), or a removed `analyse` / `phpcs` / checker step from `composer.json` scripts or a CI workflow. That config-level reach binds to a line the diff adds, modifies, or **removes**, and only when the change narrows coverage of code the diff itself touches or answers a reported finding — independent maintenance (excluding generated code the diff does not touch, dropping a rule the project never actually enabled) stays ordinary configuration upkeep, not a suppression. In its place, the rule states the expected response: rewrite the code so the finding stops being true (restructure the block, narrow or correct the type, extract a method, introduce a value object); when a finding genuinely cannot be resolved by rewriting the code, the agent never adds a suppression or weakens the configuration to quiet the tool — it **stops** and reports the finding as a blocker to whoever is driving the run, the same `Blocked: <reason>` handoff `agents/talos.md` generalizes from its sandbox-only status into its general blocked-handoff contract for this trigger too, and only the caller may decide afterward to file the underlying defect as its own tracked issue (`agents/athena.md` *Findings outside the diff*); the CR lens now declares this a finding that is never waivable by deferral, so a suppression finding is never closed by "filed as an issue" while the diff still ships it, which is what lets `@skills/process-code-review/SKILL.md`'s fix loop actually converge instead of looping on a finding it cannot resolve. Enforcement reaches the implementation side too: `@skills/resolve-issue/SKILL.md` (via `references/quality-gates.md`), `@skills/class-refactoring/SKILL.md`, `@skills/refactor-entry-point-to-action/SKILL.md`, `@skills/create-test/SKILL.md`, `@skills/test-driven-development/SKILL.md`, `@skills/rewrite-tests-pest/SKILL.md`, `@skills/create-missing-tests-in-pr/SKILL.md`, and the canonical rule twin `@rules/code-testing/general.mdc` *Code Style and Quality Gates* all state, at the step where checkers/analyzers run, that reported errors are resolved by rewriting the flagged code and never by adding a suppression annotation, pointing back at the canonical rule rather than restating it. `@rules/php/core-standards.mdc` *Documentation* trims its load-bearing-comment example to match — it no longer names a suppression justification as protected, since no suppression is ever load-bearing when none is ever compliant — and gains the benign `2>/dev/null` / `curl -s` justification `@rules/security/backend.md` *Malicious Code & Supply-Chain Indicators* still needs in its place, so the comment-deletion sweep does not strip the justification comments `skills/*/scripts/download-attachments.sh` carry under that carve-out. Pinned by `tests/Installer/CodeReviewContentTest.php` and `tests/Installer/SkillsContentTest.php`.
- ✨ **Added** `feat(core-standards)`: **the codebase's default state is no comments — unnecessary ones are now deleted, not merely never written.** The comment bar governed only the comment an agent *writes*: `@rules/php/core-standards.mdc` *Documentation* set the two limbs a new comment must clear, and `@rules/code-review/general.mdc` *Self-Documenting Code — Comment & Doc Hygiene* (#733) scoped its lens to "lines the diff **adds or modifies**; never pre-existing comments the diff does not touch". Nothing anywhere had standing to remove the noise already in the file, so the codebase could never converge — every change protected its own lines and walked past the *what*-narration around them, review after review, forever. *Documentation* gains **The codebase's default state is no comments**: opening a file to change it carries the duty to delete the unnecessary comments in the region being worked in — the narration of the statement below, the restatement of the signature, the redundant type docblock, the commented-out code, the section banner, the changelog note, the description that no longer matches — **including comments the agent did not write**, because removing a comment that carries no information cannot change behavior and is never a scope expansion. Two ceilings keep it from becoming a sweep: stay inside the changed hunks and their enclosing method / class member, never opening an unrelated file to hunt for comments; and when a comment's value is genuinely unclear, **keep it and raise it** — the bar is "carries no information the code does not already give", not "I did not need it". The keep-bar itself is unchanged: the *why*, a domain definition, a navigation pointer, or logic that is genuinely complex and cannot be made clearer by rewriting the code. Enforcement runs end to end — the CR lens widens from changed lines to **the changed hunks plus their enclosing method / class member**, judging a pre-existing comment by exactly the same bar and never as a separate "pre-existing" category, with the region as an explicit ceiling (an untouched method or file is never a finding) and a severity split that keeps the gate honest: a stale comment **on a line the diff itself touches** stays **Moderate** and blocks, while a pre-existing stale comment merely sitting in the region drops to **Minor**, since the change did not create the mismatch and blocking on it punishes the wrong commit; `@skills/resolve-issue/SKILL.md` adds **Unnecessary comments** as a fourth *Pre-existing issue handling* category landing in its own `refactor(<scope>): pre-existing — remove redundant comments in <area>` commit, which — touching no executable line — needs neither a regression test nor the *Test Coverage Contract*'s pre-refactor coverage commit and must stay comment-only (a deletion that requires a rename or an extraction is a separate item); `@skills/class-refactoring/SKILL.md` extends its comment signal to the comments **already in the class**, so a restructured class is never delivered still explained by prose written for its old shape; and `@rules/code-testing/general.mdc` gains **Comments in Tests** — the `it()` description and arrange-act-assert already say *what*, so phase labels and setup narration go, only what the body cannot say stays, and a surviving comment is updated in the same change that changes the assertion. Three boundaries keep the widening honest: **load-bearing comments are never deleted** — the one a per-row loop needs under `@rules/sql/optimalize.mdc` *Acceptable exception* and the one a benign `2>/dev/null` / `curl -s` needs under `@rules/security/backend.md` *Malicious Code & Supply-Chain Indicators* are the *condition* of an exception, so a sweep that removes them turns compliant code into a violation; the mandate explicitly **does not loosen** *Code Style* (*Never reformat unrelated existing code*) or *AI Behavior* (*Preserve existing code and do not remove unrelated logic*) — a comment in the region being changed is not unrelated, deleting one is not reformatting, and a comment is not logic; and the lens's *Gating* bullet now also yields to `@skills/class-refactoring/SKILL.md` (`MODE=cr`), so a comment whose deletion already rides along with a restructuring proposal is billed once, by that proposal, never twice. Pinned by `tests/Installer/SkillsContentTest.php` and `tests/Installer/CodeReviewContentTest.php`.
- ✨ **Added** `feat(laravel)`: **new code never designs an application Facade — the service layer caps at `BaseModelService`.** The seven Business Logic Layers never included a Facade, but nothing said so outright, and the surrounding prose actively suggested otherwise: eight layer enumerations read *"Actions, Services, Facades, controllers, jobs …"* as if a Facade were a peer of the allowed homes, and the *Pass-through Action rule* prescribed calling a Facade method directly from the entry point as its fix. `@rules/laravel/architecture.mdc` **Model Services** gains *No application Facades — `BaseModelService` is the ceiling*: every shape of the pattern is forbidden in new or materially changed code — a class extending `Illuminate\Support\Facades\Facade`, a file under `app/Facades/`, a `Facade`-suffixed class, a container alias exposing business logic as `SomeName::method(…)`, and the hand-rolled static wrapper — because a Facade hides its collaborators from the constructor signature, so the call site stops declaring what it needs and neither the container nor static analysis can follow the graph. The ceiling for a new flow is a **Model Service** extending `Pekral\Arch\Service\BaseModelService`, constructor-injected; logic routes to the layer that owns it (Model Service, Action, Repository / ModelManager, Data Validator, Data Builder). The scope line is the load-bearing half: the rule governs Facades the application **defines**, never the ones Laravel **ships**, so `Cache::` / `DB::` / `Log::` / `Storage::` call sites stay clean and `@skills/redis-patterns/SKILL.md` keeps prescribing them. Enforcement runs end to end — `@rules/laravel/architecture.mdc` CR Severity Rules marks a new application Facade **Critical**, `@rules/code-review/general.mdc` gains the **New application Facade (service-layer ceiling)** walk with its reproducer fields (Facade subclass as Faulty Example, constructor injection as Expected Behavior, a Pest `arch()` expectation as Test Hint) and gating that collapses the overlap with the ad-hoc-class, Service-role, and pass-through bullets into one finding, and `@skills/analyze-problem/SKILL.md` gains *Layer ceiling — never propose an application Facade* so the shape is refused at design time, where it actually gets invented, rather than after the call sites exist; when a Facade genuinely looks like the only workable design, it goes to **Assumptions and Missing Information** as an open question for a human instead of into the recommendation. The contradicting prose is narrowed to match: Facade drops out of the eight layer enumerations in `architecture.mdc` and `laravel.mdc`, the pass-through resolution names the Model Service as the delegation target, and the two rules that carried Facade in their titles become *Single-use Service method rule*, with the references in `@rules/code-review/general.mdc` and `@skills/class-refactoring/SKILL.md` following so no pointer is left aimed at a name that no longer exists.
- ✨ **Added** `feat(pr-summary)`: **every summary comment now opens with a TL;DR.** The GitHub comment led with an `Authors` line and a 3–5 sentence paragraph, and the JIRA comment led straight into numbered test steps — so a skimming reader had no way to learn what shipped without reading the whole thing, and the JIRA reader, by design, got no narrative at all. `@skills/pr-summary/SKILL.md` and both templates gain a `TL;DR` section directly below the assignment-verdict banner: one or two plain-language sentences naming the user-visible outcome and the reason for it, always rendered, never conditional, in the assignment language. The two-sentence cap is part of the contract — on GitHub a longer TL;DR duplicates `Summary of changes`, and on JIRA it recreates the section that target deliberately omits. The JIRA shape is now `TL;DR` + `How to test` (still no `Authors`, no `Summary of changes`, no `Available behind`), and the verdict slot plus every section inventory across the skill, both templates, and `@skills/code-review-jira/SKILL.md` follow the new opening section.
- ✨ **Added** `feat(git)`: **no commit may ship dead code — every commit is live at its own point of the history.** The green-commit invariant said each commit must *build*; nothing said its code had to *do* anything, so the horizontal split — `feat(x): add the action` followed by `feat(x): use the action` — passed every gate while shipping a commit whose class nobody calls: unreachable in production, nothing for a reviewer to judge, a no-op to revert, and invisible to `git bisect`. `@rules/git/general.mdc` *Git Rules* gains **Every commit is live** next to it: everything a commit adds — class, method, branch, parameter, enum case, route, listener, config key, translation key, column, asset — must be reached by code in that same commit or an earlier one, so the callee travels with its call site and its coverage; commits are split **vertically by concern**, never horizontally by layer; code reachable by registration (route entry, container binding, listener / scheduler registration, migration, Blade component) counts as reached when the registration lands in the same commit; the **only** code that may precede its consumer is a declared inert prerequisite (config key, off-by-default flag, additive expand migration) — a class, method, or branch never is; code nothing in the branch ever reaches is deleted rather than shuffled between commits; and the check is per commit (`git grep -n '<symbol>' <sha>` must return a use outside the declaration), repaired by folding the commit into the one that puts its code to work, never by appending the call site later. The invariant is enforced end to end: `@rules/code-review/general.mdc` *Commit Split & Atomic Deployability Proposal* gains **trigger 10 — a commit ships dead code** (the mirror image of the forward-reference trigger), a **live-commit invariant** binding its own proposal (hunks that cannot be separated without leaving one of them dead stay in one commit, every proposed row carries `live: yes` or the declared `inert prerequisite — consumed by #k`, never `live: no`), three new non-findings (registration-reachable code, a declared inert prerequisite, a package's published public API), a gating bullet routing code still unreached at `<head>` to *New PHP File — Architecture & Design Conformance* / the **Assignment Conformance Gate** instead of a pointless repartition, and a literal Suggested Fix that now ends in the per-commit reachability check; `@skills/code-review/SKILL.md` and the `code-review-github` / `code-review-jira` / `code-review-bugsnag` wrappers state the live half of the partition, and all four report templates gain a `Live` column plus the green-and-live invariant note, the per-commit reachability line in the reconciliation, and the aligned Suggested-fix text; `@skills/pr-staged-merge-plan/SKILL.md` adds check 9 *No dead code* to the per-unit shippability walk; and `@skills/resolve-issue/references/commit-planning.md` (the procedure `@skills/resolve-issue/SKILL.md` delegates to) plans each item as a vertical slice and no longer lifts a caller-less helper into its own groundwork commit — shared groundwork is ordered first only when that commit is live on its own. Pinned by `tests/Installer/CompoundEngineeringContentTest.php`, `tests/Installer/CodeReviewContentTest.php`, and `tests/Installer/SkillsContentTest.php`.
- ✨ **Added** `feat(git)`: **every commit in a pull request must be green on its own — a red or simulated-red commit never reaches the history.** `@rules/git/general.mdc` *Git Rules* gains the green-commit invariant next to the logical-partition rule: it governed *what* each commit contains but never *what state it leaves behind*, so a branch could satisfy it while carrying an intermediate commit that does not build — which makes `git cherry-pick`, `git bisect`, and `git revert` useless on exactly the history the partition rule exists to protect. Every commit in `<default-branch>..HEAD` now passes the project's gate (`composer build` here) **alone**, not merely at the branch tip; a failing test is never committed, and neither is a simulated one — no committed TDD RED step, no assertion inverted "for now", no `->skip()` / `->todo()` / `markTestIncomplete()` / commented-out assertion standing in for behavior a later commit fixes, no fixture pinned to the buggy output. A commit that cannot be made green alone is folded into the commit it depends on rather than published with an explanation in the PR description. Because a rebase replays every commit onto a new base, a **required reshape is finished only when each commit has been re-verified** — `git rebase --exec '<gate command>' <base>` — with a failing commit repaired **in place** (amend, `git rebase --continue`), never by a repair commit appended at the tip; *Pull Policy* carries the matching step 5 after the rebase. The invariant is enforced end to end: `@rules/code-review/general.mdc` *Commit Split & Atomic Deployability Proposal* adds a **red commit** trigger and binds its own proposal to a **green-commit invariant** (hunks that cannot be separated without a red intermediate stay in one commit, every proposed row carries `green: yes`, and the literal Suggested Fix now ends in the per-commit `git rebase --exec` replay); `@skills/resolve-issue/references/commit-planning.md` promotes it to a blocking planning step ahead of the cherry-pick-independence target and replays the reconciled range before the PR is opened; `@skills/test-driven-development/SKILL.md` gains *Commit boundary — the RED step is never its own commit* (RED is a working-tree state, the failing test and the change that makes it pass land in one commit made after VERIFY GREEN); and `@skills/git-workflow/SKILL.md` documents the `--exec` mechanic and the in-place repair. - ✨ **Added** `feat(analyze-problem)`: **an analysis whose solution outgrows one change now proposes the split instead of handing over an unbounded task.** `@skills/analyze-problem/SKILL.md` gains the *Large-Task Decomposition Proposal* section and a new `## 9. Task Decomposition` slot in `templates/analysis-report.md`. Four triggers fire it — the work spans more than one application area or separately shippable layer, the Implementation Outline is already a list of pull requests rather than edits, the work exceeds one session / one PR or the assignment is written as several numbered requirements, or part of it is blocked on an external answer the rest does not need. The split rules keep the result shippable: one part is one independently deliverable, independently reviewable unit that merges on its own; parts are split **by deliverable, never by activity** (*"add the invoice export endpoint"* is a part, *"write the tests"* is not); every part names its dependencies so a resolving run can pick a dependency-aware order and see what runs in parallel; and an additive part ships before the one that removes the old shape. The proposal is rendered in the tracker's own vocabulary — **GitHub**: an `EPIC` parent plus one child issue per part; **JIRA**: the analyzed issue as parent with one sub-task per part, each carrying a summary, description, and dependency list; **Bugsnag**: the GitHub shape applied to the mirrored issue from `linkedIssues[]`. Three boundaries keep it from colliding with what already exists: the EPIC mechanics stay owned by `@skills/create-issues-from-text/SKILL.md` (this section is the input it consumes); the overlap with `@skills/blueprint/SKILL.md` — both trigger on work outgrowing one pull request — is settled **by deliverable, not by size** (this section owns the tracker-shaped split of an analysis that already found the root cause, `blueprint` owns the sequenced construction plan of 3–12 one-PR steps with cold-start briefs, and anything past eight parts is always `blueprint`'s); and the skill **proposes only** — it never creates, links, labels, or transitions **the proposed parent or its children**, a prohibition deliberately scoped so the single plan artifact the *Plan artifact* step already permits (the one `agents/metis.md` publishes and hands back) keeps working. A code-review invocation skips the section entirely, exactly as it skips the plan artifact, and a solution that fits one change omits it with no "no split needed" placeholder. - ✨ **Added** `feat(laravel)`: **an Action never returns a raw array — a structured result is always a typed DTO.** `@rules/laravel/architecture.mdc` **Actions** gains the *Action return contract: a DTO, never an array* section. The moment `__invoke()` would hand back more than one value — a record, a multi-key payload, a result plus its metadata, a created-entity-plus-outcome pair — the return type is a `final readonly` DTO with promoted constructor properties under `app/Dto/{Domain}` with the `Data` suffix, because an `array` return is an opaque contract: the caller must read `__invoke()` to learn the keys, static analysis cannot check them, and an added key silently breaks every consumer that unpacked the shape. The allowed return types are enumerated (typed DTO, single scalar / `bool` / `enum` / `null` / `void`, an Eloquent model, a homogeneous list or `Collection` of one type — a homogeneous list is not a structured result and needs no wrapper), and the framework / vendor-contract exemption from `@rules/php/core-standards.mdc` *Structure* explicitly **does not apply** to a project-owned `__invoke()`; needing an array downstream is not an excuse either — the DTO is serialized at the boundary that consumes it, and the shaping that produces it stays in a Data Builder or a DTO named constructor. The matching CR finding is **Critical** and gated against the existing Moderate *public method returning a structured associative array* bullet so an Action raises exactly one finding. `@rules/laravel/laravel.mdc` *DTOs* and `@skills/refactor-entry-point-to-action/SKILL.md` carry the same contract, so an entry point that previously built an array inline comes out of the refactor returning a DTO instead of relocating the array. Pinned by `tests/Installer/LaravelRulesContentTest.php`.
- ✨ **Added** `feat(laravel)`: **every validation rule set lives as a trait in `app/Concerns/` — including a FormRequest's `rules()`.** Until now `@rules/laravel/architecture.mdc` *Validation Rules (Traits)* bound Data Validators to the traits but left a FormRequest free to declare its own rule array, so the same rule set could exist twice with two wordings. The rule is now unconditional: a rule array is never written inline at its point of use — it is published by a trait under `app/Concerns/` and composed from there by **every** consumer (FormRequest `rules()`, Data Validators, Livewire validation, Artisan-command input validation, nested rule sets inside custom `Rule` classes), so one rule set has exactly one home and one wording across the application. The trait is extracted **even for a single current consumer** and **even when it names a concrete aggregate**, which required an explicit carve-out from the whole *Shared Concerns (Traits)* placement gate: validation rule traits are exempt from all three placement conditions (*globally applicable*, *domain-agnostic*, *reusable as-is*), from the *no domain-specific logic in `app/Concerns/`* prohibition, and from the matching **Critical** *domain-specific code placed under `app/Concerns/`* finding — a rule set is a declarative input contract, not the business logic that acts on it. Without that carve-out a rule set like `InvoiceLineItemsValidationRules` would have been simultaneously mandatory in `app/Concerns/` and Critical for being there. `@rules/laravel/architecture.mdc` CR Severity Rules gain the matching **Critical** finding — *a validation rule array declared inline anywhere outside a trait in `app/Concerns/`* — gated to raise once per rule set (the existing Data Validator bullet keeps ownership when the inline rules sit there). `@rules/laravel/laravel.mdc` *Validation* and `@skills/refactor-entry-point-to-action/SKILL.md` carry the same contract, so an entry-point → Action refactor extracts the traits instead of copying rule arrays into the new Data Validator. Pinned by `tests/Installer/LaravelRulesContentTest.php`.
- ✨ **Added** `feat(php)`: **a comment is the exception, not the default — only genuinely complex logic earns one.** `@rules/php/core-standards.mdc` *Documentation* gains the comment budget: narration of the next statement, restatements of the signature, "section" banners, commented-out code, and changelog notes are noise; a comment is warranted only when it clears one of **two bars** — it carries knowledge the code cannot express (the *why*, a domain term's meaning, a navigation pointer), or the logic itself is genuinely complex (a non-obvious algorithm, an ordering / concurrency constraint, an external-system quirk) **and** that complexity cannot be removed by writing the code more clearly: rename the symbol, extract an intention-revealing method, split a mixed-responsibility method, name the magic value. Clean readable code is verified by the compiler, the tests, and every later change, while a comment is verified by nobody and quietly decays into a lie the next reader acts on, so a comment clearing neither bar describes the *what* and is not written. The same bar is enforced on review — `@rules/code-review/general.mdc` *Self-Documenting Code — Comment & Doc Hygiene Analysis* gains **Bar for keeping a comment**, which governs every finding in that dimension and states that **accuracy is not the bar, necessity is**: a comment clearing neither bar is a finding whatever its wording, and a comment is never accepted for being correct, harmless, or "adding context". `@skills/class-refactoring/SKILL.md` gains the authoring counterpart — *a comment is a refactoring signal, not a deliverable*: when touched code needs a comment to be followed, refactor the code and delete the narration, never reword the prose around an unreadable block. Existing severities are unchanged (hygiene findings stay Minor, a stale comment on a touched line stays Moderate) and both preserved exceptions — rationale / domain language and navigation pointers — still never raise a finding. Pinned by `tests/Installer/CodeReviewContentTest.php`.
- ✨ **Added** `feat(code-review)`: **every code review now proposes how to split a large change into logical, atomically deployable commits — always as a Critical finding** (#763). `@rules/code-review/general.mdc` gains the declaration *Commit Split & Atomic Deployability — a first-class review dimension* plus the canonical walk-through behind it. The review reads the real history (`git log --reverse <base>..<head>` and each commit's own diff, never the squashed diff) and asks whether it is already a logical, independently cherry-pickable partition of the change set per `@rules/git/general.mdc` *Git Rules*. Eight triggers raise the finding — a commit bundling two concerns, a concern scattered across commits, a commit that cannot be cherry-picked onto the default branch on its own (forward reference), the whole change in one commit while the assignment lists several items or phases, a subject that does not describe its own diff, expand-before-contract violated inside one commit, a `## Changes` table that disagrees with `git log`, and diff inflation with its own commit-worthy shape. The rule now defines a concrete memory file convention (`docs/memory/PROJECT_MEMORY.md` in the project being worked on, separate from the hand-maintained `CLAUDE.md`), a greppable one-lesson-per-entry format, a three-gate **promotion bar** (recurs beyond the task / cost real effort / not already captured) so only the most important lessons are stored, a per-write **curation pass** (dedup / supersede / prune / soft-cap), the read protocol, and the secrets/PII prohibition. A new write-side skill **`record-project-memory`** runs at task convergence to distil and append surviving lessons. The read side is hooked into `daidalos` (gather phase folds matching entries into the shared brief's new `## Project memory` section), `analyze-problem` (*Context extraction*), and `prepare-issue-context`; the write side is hooked into `resolve-issue` (*Final report*), `process-code-review` (*Completion*), and the `daidalos` final-report step (before brief cleanup). The file lives in the target project, never in this shared rules package, and the installer never touches it (project data, not package data), so it survives re-installation without an installer change. Also fixes a pre-existing dangling cross-reference: `daidalos` and `talos` referenced a *Blocked delegation is a hard stop* section that did not exist in the rule — it is now present.

- ✨ **Added**: opt-in installer flag `--allow-subagent-writes` that unblocks dispatched-subagent file writes (`talos`) by prepending two scoped permission entries — `Edit(//<project>/**)` and `Write(//<project>/**)` — to `permissions.allow` in the project's `.claude/settings.local.json` (effective with `--editor=claude` / `--editor=all`). A dispatched subagent runs non-interactively, so a write is denied unless the path is pre-allowed; the scoped entries grant exactly that, permanently and across headless runs. The flag is **opt-in by design** (mirrors `--allow-bundled-scripts`) — the package grants nothing by default — is **idempotent** (leaves existing allow entries untouched, adds only a missing entry), and validates the result via a new public `InstallerClaudeSettings::validateSubagentWritePermissions()` before and after the write (round-trip) so a malformed `settings.local.json` can never be produced. `settings.local.json` (personal, git-ignored) is the target because the entries carry a machine-absolute path. `docs/agents.md` *Troubleshooting — subagent file writes blocked*, `README.md`, and `docs/plans/agent-sandbox-write-blocked.md` document the remediation and flag. Supersedes the initially-shipped sandbox-block approach, which did not unblock subagent writes in practice (verified in a real project). Per user request — *funkční je Možnost A: scoped Edit/Write v permissions.allow v settings.local.json; oprav installer aby `--allow-subagent-writes` generoval tohle*.
- 📝 **Changed**: introducing a **new static-analysis / linter suppression** is now a **Moderate** code-review finding — suppressions should be fixed, not created. `@rules/php/core-standards.mdc` PHP Practices gains *Do not introduce new static-analysis / linter suppressions*, covering PHPCS (`// phpcs:ignore` / `phpcs:disable` / `@phpcsSuppress` / `@codingStandardsIgnore*`), PHPStan (`@phpstan-ignore` / `@phpstan-ignore-next-line` / new `ignoreErrors` / baseline additions), Psalm / Phan (`@psalm-suppress` / `@phan-suppress` / baseline), PHPMD `@SuppressWarnings(...)`, and the PHP `@` operator. `@skills/code-review/SKILL.md` adds a Core Analysis bullet that flags each new suppression on a changed line as **Moderate** with a fix-the-root-cause Suggested Fix. The narrow exemption: a suppression that is **both** narrowly scoped (specific rule / error identifier, single line) **and** documents inline why it is an unfixable third-party / framework false positive; `assert($var !== null)` for a required-unused variable stays the sanctioned `UnusedVariable` fix (a real assertion, not a suppression). Per user request — *pokud je v kódu nový typ ignorace (např. `@phpcsSuppress` či pro phpstan), označit to v CR jako Moderate; tyto chyby se mají řešit, ne vytvářet*.

- 📝 **Changed**: a write-capable agent blocked by the harness sandbox / permission layer is now a **hard stop, never a silent bypass**. `@rules/compound-engineering/general.mdc` gains *Blocked delegation is a hard stop* — when a dispatched implementer (`talos`) has its `Write` / `Edit` refused at runtime, the run reports the blocker with its remediation and **never** silently finishes the work in the main thread (which would bypass the implementer→reviewer loop and quality gates). `agents/talos.md` adds a `Blocked: sandbox denied file write` terminal handoff; `agents/daidalos.md` escalates it instead of implementing the change itself; `docs/agents.md` and `README.md` add a *Troubleshooting — subagent file writes blocked* section explaining that file writes are an environment grant (subagents run non-interactively) and how the human enables them (`--permission-mode acceptEdits`, `permissions.allow`, or sandbox working-tree access). - 📝 **Changed**: public methods must now return typed **DTOs instead of raw associative arrays**. `@rules/php/core-standards.mdc` Structure gains a return-value counterpart to the >4-parameter rule — when a public method produces a structured set of values (a record, a multi-key payload, an array shape with named keys) it returns a `final readonly` DTO, not an `array`; `@rules/laravel/architecture.mdc` DTOs adds *Public methods return typed DTOs, not associative arrays*, tightens the Data Builder return contract (DTO by default, normalized array only for a framework/vendor write-payload contract), and lists the violation under CR Severity *moderate*; `@skills/code-review/SKILL.md` enforces it as a **Moderate** finding on every diff. Exemptions (cited explicitly where enforced): single scalar / `bool` / `void` returns, a homogeneous list or `Collection` of one type, and array shapes fixed by a framework / vendor contract (`toArray()`, `jsonSerialize()`, `Arrayable`, `casts()`, FormRequest `rules()`, overrides of a `vendor/`-owned signature). - 📝 **Changed**: non-default branches must be rebased onto the latest default branch when they are pulled, keeping every side branch current with the default branch. `@rules/git/general.mdc` gains a **Pull Policy** section: the default branch (resolved by name — `main` on some repos, `master` on others, never hardcoded as `origin/main`) is pulled directly, but any feature / fix / PR branch is synced in a fixed order — `git fetch origin`, `git pull --rebase` to take the branch's own remote first, then `git rebase "origin/$DEFAULT_BRANCH"` to bring the default branch in, resolve conflicts, and `git push --force-with-lease` (no trailing `git pull`, which would replay the commits onto the old remote tip and undo the sync); when that rebase changes `composer.lock`, `composer install` runs immediately so the installed packages match the new lockfile. - ✨ **Added**: first-class Bugsnag tracker support, bringing Bugsnag to parity with the GitHub and JIRA flows. Until now Bugsnag was a pass-through (the detection table only said *"treat as runtime error, prefer TDD"* and reports were redirected to a mirrored GitHub issue); there was no loader, no comment publisher, and no direct API contact. This change adds a deterministic script pair under the new `skills/code-review-bugsnag/scripts/` directory, mirroring `code-review-github/scripts/` and `code-review-jira/scripts/` exactly. **`load-issue.sh <URL|TRIPLE>`** is the single deterministic entry point for Bugsnag context: it accepts an `app.bugsnag.com/<org>/<project>/errors/<id>` URL or an `<org>/<project>/<error-id>` triple, reads a Data Access API token from `BUGSNAG_TOKEN` (alias `BUGSNAG_AUTH_TOKEN`; never read from a file, never written anywhere), resolves the dashboard slugs to numeric API ids (org slug → org id → project slug → project id, paginating projects via the `Link: rel="next"` header), then fetches the error, its comments, and its latest event, and emits one stable JSON document — `errorClass` / `message` / `context` / `status` / `severity` / `events` / `firstSeen` / `lastSeen`, `linkedIssues[]` (the mirrored GitHub issue/PR), `comments[]`, `groupingFields`, and a slimmed `latestEvent` carrying the in-project `stacktrace` frames (the entry point for a TDD reproduction), app / device / request / user context, and breadcrumbs. **`upsert-comment.sh <URL|TRIPLE> -`** is the append-only comment publisher (same always-new-comment-per-run model as the GitHub helper; Bugsnag renders plain text, so no hidden per-actor marker — the token identifies the author). Both scripts use `curl` + `jq`, the `Authorization: token <TOKEN>` + `X-Version: 2` headers, and the deterministic exit-code contract (`1` usage, `2` missing tool / token, `3` API failure). The requiring skills now consume this logic: `skills/resolve-issue/references/source-detection.md` points the Bugsnag row at the loader (Bugsnag MCP fallback), `skills/resolve-issue/SKILL.md` gains a Bugsnag project-ownership check (via `linkedIssues[]`), a Bugsnag loader branch in the fetch step, Bugsnag in the read-`comments[]`-directly step, a non-technical report posted **directly on the Bugsnag error** (mirrored to the linked GitHub issue), and a Bugsnag-specific follow-up that — like JIRA status transitions — leaves marking an error *fixed* to a human; `skills/code-review/SKILL.md` and `skills/assignment-compliance-check/SKILL.md` gain Bugsnag loader branches (the error class / message / context / stacktrace is the assignment, the linked GitHub issue supplies any human-authored acceptance criteria). A new read-only wrapper `skills/code-review-bugsnag/SKILL.md` (modeled on `code-review-jira`) runs the standard sub-review chain on the linked PR, posts technical findings on the GitHub PR, and delegates the non-technical summary to `@skills/pr-summary/SKILL.md` posted on the Bugsnag error. The design rationale and step plan are captured in `docs/plans/bugsnag-integration.md`. README skill count bumped 48 → 49. Per user request — *navrhni a zprovozni řešení pro Bugsnag, které umí všechno co github a jira skills, ideálně přes CLI/MCP; ověř komunikaci a uprav požadující skilly*.
